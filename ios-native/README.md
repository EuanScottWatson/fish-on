# Fish On Swift migration

This SwiftUI implementation uses the existing Fish On server and currently builds under the separate bundle ID `uk.fishbook.homelab.nativepreview`. Keep the installed React Native app: offline drafts cannot automatically transfer between the two app containers. Sync or otherwise preserve those drafts before migrating. The native version is still being verified and must not yet be presented as a complete replacement.

Native code includes catch capture and offline drafts, Photos and camera, metadata, local editing and sync, identification crop, trips, guide filters and licensed imagery, GBIF range, discovery maps, statistics, and country assignment. The countries endpoint requires the separate candidate server update, which has not been deployed. Some features and error cases require further parity review and physical-device tests. In particular, the simulator tests cannot verify camera, Photos, location permissions, Tailscale or touch ergonomics on a real iPhone.

The app tries a user-specified address, then the configured LAN and Tailscale addresses. It sends write requests only to the selected server and retains unsynchronised drafts on failure. UI tests use a synthetic server at 127.0.0.1:18782 and disposable fixture data; never point tests at production or put user data in this public repository. Use GitHub Actions to run Swift tests and build a signed-later IPA. iLoader can sign it for side-by-side installation.
